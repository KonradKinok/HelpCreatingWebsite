1.1 Nowy projekt

      1.2 GitHub Desktop

      W GitHub Desktop wybierz:

      1. File -> New repository... (Ctrl+N)
      2. Uzupełnij: Name
      3. Zaznacz: Initialize this repository with a README
      4. Jeżeli projekt będzie tworzony w React + TypeScript + Vite to w Git ignore wybierz Node. To jest właściwy .gitignore dla większości projektów JavaScript/TypeScript opartych o Node.js (React, Vite, Next.js, Express itd.). Będzie on ignorował m.in.:
        • node_modules/
        • logi (*.log)
        • niektóre pliki tymczasowe
        • pliki środowiskowe (w zależności od konfiguracji)
      5. Choose a license: MIT (jeśli projekt ma być otwartoźródłowy) albo None (jeśli na razie nie chcesz dodawać licencji)
      6. Na koniec wybierz: Create repository

      Po utworzeniu lokalnego repozytorium otwórz Visual Studio przez: Open in Visual Studio Code

      1.3 Visual Studio Code

      Po otwarciu Visual Studio Code, uruchom i przejdź na zakładkę: Terminal

      W terminalu wpisz: npm create vite@latest . (kropka na końcu jest wymagana) i naciśnij enter

      Kluczowa jest tutaj kropka . — oznacza "utwórz projekt w bieżącym katalogu", czyli bezpośrednio w ApiTest.

      Po wpisaniu pojawi się komunikat:

                  Need to install the following packages:
            create-vite@9.2.1
            Ok to proceed? (y)

      Wpisz: y i naciśnij enter

      Po wpisaniu "y" pojawi się komunikat:

                  ◆  Current directory is not empty. Please choose how to proceed:
            │  ○ Cancel operation
            │  ○ Remove existing files and continue
            │  ● Ignore files and continue
            │  ↑/↓ to navigate • Enter: confirm
            └

      Wybierz: Ignore files and continue i naciśnij enter

      Ponieważ w katalogu ApiTest są utworzone pliki przez GitHub Desktop, przede wszystkim README.md i .gitignore. Nie chcemy ich usuwać.

      Nie wybieraj Remove existing files and continue, bo ta opcja może usunąć istniejące pliki z katalogu przed utworzeniem projektu.

      Po wybraniu Ignore files and continue pojawi się komunikat:

                  ◇  Current directory is not empty. Please choose how to proceed:
            │  Ignore files and continue
            │
            ◆  Package name:
            │  apitest
            └

      Vite pyta o nazwę pakietu npm

      Możesz zostawić apitest i po prostu nacisnąć Enter.

      Dlaczego jest apitest, a nie ApiTest? Nazwy pakietów npm powinny być pisane małymi literami, więc Vite proponuje poprawną nazwę.

      Po naciśnięciu enter pojawi się komunikat:

                  ◆  Select a framework:
            │  ● Vanilla
            │  ○ Vue
            │  ○ React
            │  ...
            │  ↑/↓ to navigate • Enter: confirm
            └

      Strzałką ↓ przejdź na React i naciśnij enter

      Po naciśnięciu enter pojawi się komunikat:

                  ◆  Select a variant:
            │  ● TypeScript
            │  ○ TypeScript + React Compiler
            │  ○ JavaScript
            │  ...
            │  ↑/↓ to navigate • Enter: confirm
            └

      Strzałką ↓ przejdź na TypeScript i naciśnij enter

      Po naciśnięciu enter pojawi się komunikat:

                  ◆  Which linter to use?
            │  ● Oxlint
            │  ○ ESLint
            │  ↑/↓ to navigate • Enter: confirm
            └

      Strzałką ↓ przejdź na ESLint i naciśnij enter

      ESLint jest rozwiązaniem starszym, bardzo dojrzałym i ma ogromny ekosystem pluginów. Znajdziesz też znacznie więcej poradników i odpowiedzi dotyczących jego konfiguracji w React + TypeScript.

      Oxlint jest nowszym linterem napisanym w Rust. Jego dużą zaletą jest przede wszystkim szybkość. Jest obecnie coraz szerzej stosowany, ale ESLint nadal daje bardzo szeroki ekosystem i będzie dobrym wyborem do projektu, który dopiero tworzysz.

      Później będziesz mógł uruchomić kontrolę całego projektu poleceniem:

                  npm run lint

      npm run lint sprawdza Twój kod pod kątem błędów i problemów wskazywanych przez linter. W Twoim przypadku, ponieważ wybrałeś ESLint, uruchomi ESLint.

      Ważne: nie uruchamia aplikacji i standardowo nie zmienia kodu — przede wszystkim go analizuje.

      Po naciśnięciu enter pojawi się komunikat:

                  ◆  Install with npm and start now?
            │  ● Yes / ○ No
            └

      Strzałką -> przejdź na Yes i naciśnij enter

      Ta opcja zrobi za Ciebie od razu dwie rzeczy:

      • npm install — zainstaluje wszystkie potrzebne pakiety/zależności projektu, m.in. React, TypeScript, Vite i ESLint. Powstanie też katalog node_modules
      • Uruchomi projekt — odpowiednik npm run dev, czyli wystartuje lokalny serwer Vite.

      Po naciśnięciu enter pojawi się komunikat:

                   VITE v8.3.4  ready in 399 ms

              ➜  Local:   http://localhost:5173/
              ➜  Network: use --host to expose
              ➜  press h + enter to show help

      Gotowe — Vite + React + TypeScript + ESLint są zainstalowane, a projekt działa.

      Otwórz w przeglądarce adres pokazany przez Vite:

                  http://localhost:5173/

      Powinieneś zobaczyć domyślną stronę startową Vite/React.

      To, co widzisz w terminalu, oznacza:

      Vite uruchomił serwer deweloperski w 399 ms.

                  VITE v8.3.4  ready in 399 ms

      Tutaj działa Twoja aplikacja na Twoim komputerze.

                  Local: http://localhost:5173/

      Opcja pozwalająca później udostępnić aplikację innym urządzeniom w Twojej sieci lokalnej 

                  Network: use --host to expose

      To jest bardzo przydatne przy tworzeniu strony responsywnej, bo możesz pisać kod na komputerze w VS Code, a jednocześnie oglądać stronę na prawdziwym telefonie

      Jak tego użyć

      Najpierw zatrzymaj obecnie działający Vite:

                  Ctrl + C

      Następnie zamiast:

                  npm run dev

      uruchom:

                  npm run dev -- --host

      Vite powinien pokazać coś podobnego:

                  VITE v8.3.4  ready in 300 ms
            ➜  Local:   http://localhost:5173/
            ➜  Network: http://192.168.1.15:5173/

      Teraz:

      • na komputerze korzystasz z http://localhost:5173/
      • na telefonie otwierasz adres z pozycji Network, np. http://192.168.1.15:5173/.

      Komputer i telefon powinny być podłączone do tej samej sieci lokalnej, np. tego samego domowego Wi-Fi
